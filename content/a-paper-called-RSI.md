# 一篇把“递归自改进”吹得很响的论文，最后只测出了Agent会改坏自己的数据

最近看了一篇叫RSIBench-Data的论文。标题很长，核心就一句话：测大模型Agent能不能自己当数据研究员，看着模型失败的证据，自己设计更好的训练数据，再迭代改进。

递归自改进听起来很性感。真正落地时，最卡的一步往往是数据中心的那一环——诊断缺口、设计策略、训练、拿反馈、再改。模型失败了，你得把失败证据变成更好的训练数据，然后再训一次，再看结果。这个闭环如果靠人来做，慢且贵；如果能让Agent自己完成，递归自改进才有可能真正跑起来。

现有很多后训练基准把研究决策、优化器、服务、评估系统全搅在一起。分数一出来，你根本分不清是Agent真的会做数据研究，还是旁边的系统在帮它。换数据策略的同时可能也换了训练超参、评估协议或者服务方式，最后成绩涨了，却不知道涨在哪。这种纠缠让“Agent会不会自己做研究”这件事变得不可测量。

这篇论文的做法很直接：把其他全部锁死。底座模型固定成Qwen/Qwen3.5-35B-A3B-Base，训练接口固定成Tinker上的LoRA SFT，评估固定用Harbor编排的E2B沙箱跑官方测试，时间和算力预算也统一。Agent唯一能做的事，就是提出训练数据策略加上少量允许的配置，提交训练，拿到分数和诊断信息，然后根据反馈改策略，再提交，循环到预算用完。最终用官方测试集给选中的checkpoint打分。

测了四个前沿Agent：Claude Code Opus-4.8、Claude Code Sonnet-5，以及两个Codex gpt-5.6的变体。任务覆盖软件工程、终端操作、科学问答和数学，具体是SWE-bench Verified、SWE-bench Multilingual、SWE-bench Pro、Terminal-Bench 2.0、GPQA Diamond和AIME 2026。

结果很直白。58.33%的设置里，Agent能通过反馈把第一次有效尝试的成绩再往上推一点。说明它确实能做出一些有用的数据中心发现。但不稳定。达到历史最高分后还继续搜索的那些run里，78.26%最后分数反而掉了下去，剩下的只是回到峰值。进步是非单调的。好策略经常出现在早期或中期，后面容易把成绩改坏。可执行任务上成绩依然很弱，SWE-Pro最高官方分才9%，Terminal-Bench最好也就20%左右。数学任务增益相对更稳更大一些。

成功的轨迹里能看到一些共同模式。诊断得准，能正确识别能力缺口；监督信号来自真实验证，而不是空造的合成完成；数据和目标行为对齐，而不是随便堆数据；明确保留历史最强checkpoint，防止回退。没有这些，循环就变成噪音。失败的时候常见的是误诊、监督错位，以及过了峰值还继续改导致的回退。

到这里其实已经清楚了。这篇论文没有解决“为什么经常改坏、怎么让它稳定提高”的问题。它只是干净地测出了现象，分析了几个模式，然后开源代码。是一个基准论文，不是方法论文。真正难的“让Agent稳定不回退”完全没碰。它提供的是一个可审计的测试床，让后面的人可以在相同约束下继续测、继续改。但如果你期待它给出解决方案，那它确实偏空。

作者主要来自Evolvent AI和新加坡国立大学，目前只是挂在arXiv上的预印本，2026年7月28日提交，没有正式会议接收的公开信息。就是快速搭一个固定参数的沙箱，跑几个benchmark，报数字，开源仓库，然后结束。

这种东西现在很多。先有工具，再硬找应用场景；隔离问题、建测试床、报几个百分比，就当成贡献。真正卡人的核心问题没有被推进，why-what-how也没有真正跑通。学术圈里这种密度越来越高，信噪比越来越低。挂个arXiv、测出“会一点但不稳定”、分析几个模式、开源代码，就完事了。解决实际问题的密度却在下降。

以后再遇到这种论文，标准很简单。有没有真正卡人的核心问题，是不是拿着锤子找钉子，有没有给出实际路径或者至少把失败边界说清楚。不满足就直接跳过。对想解决实际问题的人来说，这个过滤是必要的。真正有价值的研究通常同时满足：问题真实且卡人，不是先有工具再硬找应用，至少给出可验证的路径或明确的失败边界。大量预印本和会议论文做不到这三点，只是换皮测基准、报数字、开源仓库。直接过滤掉，效率更高。
