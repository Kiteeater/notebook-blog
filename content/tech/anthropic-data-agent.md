企业里真正能跑起来的 data agent，核心难题从来不是模型会不会写 SQL。表多、口径乱、业务概念模糊，才是把准确率打到地下的东西。Anthropic 内部把业务分析查询的自动化率做到大约 95%，整体准确率也在这个量级，靠的是一套很硬的上下文和流程设计。把这套设计讲清楚，比再堆一个新框架更有用。

先把场景说死。这里说的 data agent，是那种接公司数据仓库，用自然语言回答业务问题的系统。用户问上季度净收入、某产品线活跃用户、漏斗转化，agent 要自己找到正确的表和字段，按官方口径算出数字，而不是随便生成一段看起来像 SQL 的文本。OpenAI 内部也有类似的 Kepler，Delivery Hero 有 QueryAnswerBird，路线都接近，但 Anthropic 把 Skills 用到了极致。

## 准确率低的三个根因

准确率低的时候，问题通常落在三处：

1. **概念和实体对不上**——同一个"收入"能对应好几张表和几种算法。
2. **数据在变**——文档和知识跟着变旧。
3. **检索空间太大**——模型根本找不到该看的那几张表。

直接把完整 schema 塞进 prompt 不现实，几万张表、上百万字段，上下文装不下。纯向量检索历史 SQL 也帮不上太多忙，Anthropic 自己试过，准确率几乎没动。

## 解法：两层知识 + Skills 流程

他们的解法是把知识拆成两层，再用 Skills 把流程写死。

### 第一层：数据基础和真相来源

数据仓库里要有清晰的规范模型，尽量减少重复和近似的表。更关键的是**语义层**。语义层把业务指标编译成全公司唯一、可直接调用的定义。净收入怎么算、活跃用户用哪个时间窗口、必须排除哪些测试数据，全部写在这里。

agent 被强制要求先查语义层。能直接命中就调用函数拿数，数字是确定的，不需要自己拼 SQL。语义层覆盖不到的长尾问题，才往下走。

### 第二层：Skills

Skills 是文件夹，里面是 markdown 指令和资源文件。Claude 启动时只把每个 skill 的名称和简短描述放进系统提示，大概几十个 token。用户问题匹配上描述，才动态加载完整内容。这样既不会把上下文撑爆，又能按需注入专业知识。

他们把 Skills 做成成对设计。一个叫 **Knowledge Skill**，一个叫 **Runbook Skill**。

## Knowledge Skill：路由器

Knowledge Skill 的指令很明确：先查语义层。语义层没有覆盖，就加载对应业务领域的参考文件。

这些参考文件不是全量字段百科，而是按 domain 精选的大约三十个文档，比如收入、活跃用户、留存、销售管道。每个文件写清楚这个主题下该看哪些表、关键字段是什么、正确的 join 路径、必选的过滤条件，以及常见的坑。

字段描述只覆盖高频和容易混淆的部分，冷门字段靠表元数据补充。文件和数据模型放在同一个仓库里，schema 变更时 CI 能同步检查文档是否过期。

## Runbook Skill：流程手册

Runbook Skill 编码资深分析师会怎么做：

1. 先澄清模糊点
2. 再通过 Knowledge Skill 找数据源
3. 再执行查询
4. 最后用对抗性的 review 子 agent 检查结果

常用分析模式也写在里面——留存曲线、漏斗、比率分解——避免每次从零发明。请求太模糊时，它强制 agent 先提问，而不是硬猜一个答案。时间范围不清楚、口径有歧义、粒度不明确，都要问回来。

## 两层配合：从猜到匹配

两层配合以后，意图识别就不再依赖模型自由发挥。

用户问题进来，先匹配 Skills。Runbook 启动流程，Knowledge 负责把模糊概念映射到有限的候选实体。搜索空间被人工压缩，优先级被写死，流程被固化。

从"在几万张表里猜"变成"在官方定义和几十个说明书里匹配"。这就是准确率能从百分之二十几跳到九十五的原因。

## Vague 请求：宁可多问一轮

Vague 请求的处理也写进了流程。宁可多问一轮，也不要给出错误但看起来很自信的数字。

Knowledge Skill 里不会为每个字段塞长篇业务背景，那样维护成本和上下文都会失控。只保留真正影响映射的关键信息。

## 本质：把分析师判断变成程序

整套东西看起来像多了一堆文档和规则，实际上是把"资深分析师的判断"变成了可执行的程序。

- **语义层**管官方口径
- **domain 文件**管长尾和坑点
- **Skills** 管路由和流程

模型负责推理和生成，但被牢牢框在已经治理好的空间里。

企业里要做类似系统，最贵的往往不是模型调用，而是把数据基础、语义层和这些参考文件维护起来。做不到这一点，再强的模型也只是在更大的搜索空间里更快地犯错。
