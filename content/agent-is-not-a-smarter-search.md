很多人对 Agent 的理解停留在「更聪明的搜索框」——问一句，答一句。这是对它最大的浪费。

## 闭环，不是回答

搜索框是**开环**的：你提问，它回答，结束。无论答案对不对，系统都不会知道，也不会因此改变什么。

Agent 的本质是**闭环**：

1. 感知（拿到任务）
2. 决策（选择一个动作）
3. 行动（调用工具）
4. 观察（拿到结果）
5. 回到第 2 步

这个循环能转起来，Agent 才「活」了。否则它只是一个会说话的数据库。

## 工具是 Agent 的手

没有工具的 LLM，像一个被绑住手脚的专家——满腹经纶，什么都做不了。

```python
@tool
def search_codebase(query: str) -> str:
    """在代码库中搜索相关片段"""
    return grep(query)
```

工具的设计有三个原则：

- **粒度合适**：太细 Agent 用不过来，太粗失去灵活性。
- **反馈清晰**：工具返回的错误信息，要能让 Agent 自己纠正。
- **边界明确**：每个工具只做一件事，别让 Agent 猜它能干什么。

## 记忆是 Agent 的脊柱

短期记忆在上下文窗口里，长期记忆要靠外部存储。但比「存什么」更难的是**忘什么**。

一个什么都记的 Agent，会被无关信息淹没；一个什么都不记的 Agent，每次都从零开始。好的记忆系统，是**有选择性的遗忘**。

## 所以

别再问「Agent 能回答什么问题」，去问「Agent 能完成什么任务」。前者是搜索框思维，后者才是 Agent 思维。
